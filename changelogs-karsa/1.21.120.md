# 1.21.120-r1
Released 12th November 2025.

This release is a consolidation of protocol/data merges pulled from NetherGamesMC plus a set of repository-specific adjustments and features added by KarsaMine‑MP to support our network's operational needs. For a concise list of notable areas changed and file references, see the sections below.

## pmmp major-next tracking
This fork follows and merges changes from pmmp's `major-next` branch as part of our maintenance policy. The `major-next` branch contains forward-looking, sometimes backwards-incompatible API changes and behaviour adjustments that are not present on `stable`.
- For a quick overview of the differences between `stable` and `major-next`, you can consult the GitHub compare page:
  - https://github.com/pmmp/PocketMine-MP/compare/3d05e43...0a0bff5

## Changes included from NetherGamesMC/PocketMine‑MP
- This release includes merges and fixes from the NetherGamesMC distribution on top of the pmmp `stable` branch. NetherGamesMC maintains their own PocketMine‑MP fork and provides protocol/data merges, bugfixes and stability improvements.
- Compare NetherGamesMC `stable` with pmmp `stable` to see what they have changed:
  - https://github.com/pmmp/PocketMine-MP/compare/c44b66c...NetherGamesMC:cd1de6c

# 1.21.120-r2
Released 21st November 2025.

## Core
- Updated issue reporting link used in release message (commit d709a941f).
- Waterlogging system updates and related block behaviour fixes (commit 2825471a5).
- `ScriptPluginLoader` now generates name/version when missing; example plugin added with documentation (commits 50f92fc1a, ccc55397d, c6945bdd2, e402696c9).
- Use `pocketmine.`-prefixed localization key for spawnpoint success (commit 95b8bd4c3, #6899).
- Improved error reporting in `FetchAuthKeysTask` to return more useful errors when key fetching fails (commit 4436aeec2).
- Implemented infinite effects support (commit 1fbc9302b, #6866).
- Multiple translation updates from Crowdin across branches (various commits).

## API
- Command overloading system improvements (commit 2fc52ce6b):
  - The commit refactors and centralizes how command overloads are constructed and registered. Instead of instantiating concrete overload classes (e.g. `ExecutorOverload`, `BranchingOverload`) directly, the codebase now uses a single entrypoint: `OverloadBuilder`.
  - `OverloadBuilder::single(...)` is provided as a convenience for non-branching (single-overload) commands.
  - `OverloadBuilder::make()` plus `->branch(...)`/`->executor(...)` is used for branching commands.
  - The `branch(...)` callback signature changed: it now receives an `OverloadBuilder $childBuilder` and should configure the child builder (via chaining) instead of returning a built `BranchingOverload` object. Returning a BranchingOverload from the callback is no longer allowed.
  - Concrete overload classes are treated as internal implementation detail and are expected to be created only by the builder.

## Performance
- Simplex noise optimization: avoid repeated property reads, improving performance ~10% in affected codepaths (commit 28f576d5c).
